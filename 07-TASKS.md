# 07 · Задачи

Одна задача — один коммит. Не начинать следующую, пока критерий готовности предыдущей не выполнен на реальных данных, а не на моках.

Формулировка для Claude Code: *«Прочитай CLAUDE.md, 02-INGEST.md и выполни задачу T{N} из 07-TASKS.md. Не выходи за её границы.»*

---

## T0 · Ручная подготовка (Karoline, не агент)
`01-UTM-SETUP.md`, чеклист в конце файла. **Блокирует всё остальное.**

---

## T1 · Скелет
Репозиторий, `uv`, `.env.example`, `src/db.py` с пулом `psycopg`, применение миграций 001–003 по порядку, `sync_run` пишется при любом запуске.

**Готово когда:** `uv run python -m src.db --check` печатает список таблиц и содержимое `config`.

---

## T2 · Синк сущностей Meta
`src/meta/client.py` — httpx, `appsecret_proof`, пагинация по курсору, чтение `X-Business-Use-Case-Usage`, пауза при утилизации выше 75 %.
`src/meta/entities.py` — кампании → адсеты → объявления → креативы → ассеты. Разбор `object_story_spec` и `asset_feed_spec` по правилам из `02-INGEST.md`. Скачивание файлов, `sha256`, загрузка в Storage, пропуск при совпадении хеша.

**Готово когда:** повторный запуск не создаёт дубликатов; число экспозиций совпадает с числом объявлений в кабинете; у динамических креативов проставлен `variant_resolution = 'dynamic_unresolved'`.

---

## T3 · Синк перформанса
`src/meta/insights.py` — асинхронные отчёты, опрос с экспоненциальной паузой, окно `RESTATEMENT_WINDOW_DAYS`, запись с `as_of = current_date`, `on conflict do nothing`.
Отдельная ночная задача схлопывает дни старше окна.

**Готово когда:** два запуска в один день не растят таблицу; запуск на следующий день добавляет новый `as_of`; `v_restatement` возвращает осмысленные строки.

---

## T4 · Лиды и воронка
Три пути из `02-INGEST.md`, каждый в своём модуле. Мусорные значения `utm_content` не выбрасываются, а попадают в `raw_utm` с `attribution_path='unmatched'`. Правило `first_touch` из `config` — повторный синк не переписывает привязку. Стадии воронки и сделки из CRM.

**Готово когда:** заполнены `lead`, `funnel_event`, `deal`; распределение по `attribution_path` выводится одним запросом.

---

## 🚦 ГЕЙТ · `scripts/reconcile.py`
`06-GATE.md`. Печатает отчёт, возвращает ненулевой код при провале.

**Дальше не идти, пока не пройден дважды с интервалом в неделю.**

## T5 · Крон
`.github/workflows/sync.yml`, каждые 4 часа: сущности → инсайты → лиды. Уведомление при `status='failed'` или при отсутствии успешного запуска дольше 8 часов.

**Готово когда:** 7 дней подряд без ручных запусков, все строки `sync_run` в `ok`.

---

## T6 · Метрики
Проверка миграции 002 на живых данных. Валидация функций: `wilson_ci` при нуле испытаний возвращает `null`, не падает; `cost_ci` при нуле событий возвращает `null`, не делит на ноль; `v_fact_settled` не пропускает будущие дни.

**Готово когда:** `select * from v_exposure_metrics limit 20` даёт непустой результат с заполненными интервалами.

---

## T7 · Запись решений
`src/decisions/run.py` — ежедневный проход по `v_decision`, запись в `decision_log`, идемпотентно по `(exposure_id, decided_on)`. Порог `min_cohort_size` соблюдается: в маленькой волне вердикты не выносятся.

**Готово когда:** за неделю в `decision_log` появились вердикты минимум трёх разных типов, и `no_decision` — не самый частый.

---

## T8 · Поле гипотезы
Форма для заполнения при запуске: `statement`, `mechanism`, `primary_metric`, `predicted_direction`. Привязка `hypothesis_id` к экспозиции. Список экспозиций без гипотезы висит на видном месте.

**Готово когда:** у всех запущенных за неделю экспозиций гипотеза заполнена.

**Не откладывать.** Заявленное намерение не восстанавливается задним числом ни из ассета, ни из статистики. Всё, что запущено без него, потеряно для анализа навсегда.

---

## T9 · Интерфейс
Next.js на Vercel, одна страница: таблица экспозиций текущей волны — превью ассета, ключевые метрики с интервалами, вердикт, диагноз, ступень остановки. Фильтры по волне, сегменту, `traffic_mode`, вердикту. Кнопка «принято» пишет `acted_on`.

**Готово когда:** еженедельное решение по креативам принимается отсюда, без Ads Manager.

---

## T10 · Ручной ввод evidence
Форма для `evidence`: находка, метрика, эффект, интервал, скоуп, уровень доказательности, объём выборки, конфаундеры. Уровень выставляется человеком, не выводится автоматически. Находки старше N волн без перепроверки подсвечиваются как `weakening`.

**Готово когда:** в таблице есть первые находки с указанным уровнем и датой проверки.
