# library-pulse · Creative OS

Библиотека рекламных креативов Meta, склеенная со сквозной воронкой до сделки,
с автоматической диагностикой каждого объявления.

Бриф — [CLAUDE.md](CLAUDE.md). Задачи — [07-TASKS.md](07-TASKS.md).
Порядок жёсткий: `T0 → T1 → T2 → T3 → T4 → ГЕЙТ → T5…T10`.
Интерфейс не начинается, пока не пройден гейт из [06-GATE.md](06-GATE.md).

## Известные ограничения

Сознательно принятые сужения скоупа — по правилу из [06-GATE.md](06-GATE.md).

- **Click-to-WhatsApp не поддерживается.** Трафика по этому пути нет, `src/leads/ctwa.py`
  в A1 не пишется. Значение `ctwa` в `lead.attribution_path` остаётся в схеме на случай,
  если путь появится позже. Если WhatsApp-трафик запустят — матч-рейт поедет вниз молча,
  и это заметит только гейт.
- **Instant Forms не поддерживаются.** Лид-формы не используются, `src/leads/leadgen.py`
  в A1 не пишется. Из трёх путей склейки остаётся один — T4 сводится к `utm.py` + `crm.py`.
- **Склейка держится на одной цепочке.** Единственный путь атрибуции — UTM → лендинг →
  форма → HubSpot. Запасного нет: любой обрыв в этой цепочке уводит матч-рейт ниже
  порога гейта в 80 % целиком, а не частично. Отсюда цена шага 3 из
  [01-UTM-SETUP.md](01-UTM-SETUP.md) — пройти путь лично до начала T4.

## Подключение к базе

Только **Session pooler**, порт 5432:

```
postgresql://postgres.<ref>:<пароль>@aws-0-sa-east-1.pooler.supabase.com:5432/postgres
```

Direct connection (`db.<ref>.supabase.co`) не работает: у хоста только AAAA-запись,
а маршрута до этой сети по IPv6 с рабочих машин нет — соединение висит до таймаута
пула. Transaction pooler на 6543 не держит prepared statements, о которые спотыкается
`psycopg`.

## Запуск

```bash
uv sync
cp .env.example .env        # заполнить DATABASE_URL
uv run python -m src.db --migrate
uv run python -m src.db --check
```

`--migrate` применяет `migrations/*.sql` по порядку имён, по одной транзакции на файл.
Повторное применение отсекается реестром `schema_migration`, а не самим SQL:
файлы схемы неидемпотентны намеренно, они часть спеки и правятся только новым
нумерованным файлом.

`--check` печатает таблицы, представления и содержимое `config` — это критерий
готовности T1.

Оба запуска пишут строку в `sync_run` (инвариант 5).
