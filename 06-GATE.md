# 06 · Гейт: сверка перед тем, как строить дальше

Запускается в конце второй недели, после T4. Пока не пройден — интерфейс, метрики и лестница решений не начинаются.

Скрипт: `scripts/reconcile.py`. Печатает отчёт и возвращает ненулевой код, если хоть один критерий провален.

---

## Критерии прохождения

Все четыре одновременно, на окне последних 30 дней:

| # | Критерий | Порог |
|---|---|---|
| 1 | Расхождение по спенду с Ads Manager | ≤ 1 % |
| 2 | Доля лидов, привязанных к экспозиции | ≥ 80 % |
| 3 | Расхождение по числу лидов с CRM | ≤ 3 % |
| 4 | Экспозиции без ассета | 0 |

Дополнительно, не блокирует, но смотрится глазами: величина переписывания истории Meta.

## Запрос 1 · Спенд

```sql
select date_trunc('week', day) as week,
       round(sum(spend), 2) as spend
from v_fact_latest
where day >= current_date - 30
group by 1 order by 1;
```

Сверить понедельно с Ads Manager вручную, на том же окне атрибуции. Расхождение больше 1 % — почти всегда одна из трёх причин: пропущен рекламный кабинет, двойной учёт из-за разбивки по плейсментам, либо взяты все `as_of` вместо последнего.

## Запрос 2 · Матч-рейт лидов

Главная цифра гейта.

```sql
select attribution_path,
       count(*) as leads,
       round(100.0 * count(*) / sum(count(*)) over (), 1) as pct
from lead
where created_at >= current_date - 30
group by attribution_path
order by leads desc;
```

`unmatched` должно быть ≤ 20 %. Если больше — разобрать причины, прежде чем идти дальше:

```sql
select raw_utm->>'utm_content' as raw_value, count(*)
from lead
where attribution_path = 'unmatched'
  and created_at >= current_date - 30
group by 1 order by 2 desc limit 30;
```

Типичная картина и что значит:

| Что видно в `raw_value` | Диагноз |
|---|---|
| `{{ad.id}}` буквально | макрос не подставился — неверный синтаксис в поле URL parameters |
| `null` / пусто | лендинг не передаёт параметр в форму, либо теряет при навигации |
| `undefined` | JS на лендинге читает параметр раньше, чем тот появился |
| осмысленное имя креатива | остались старые ручные UTM, не перезаписаны |
| числовой ID, но нет в `exposure` | объявление удалено, либо кабинет не в списке синка |
| много лидов вообще без `raw_utm` | трафик идёт через WhatsApp или Instant Forms, путь не подключён |

Последняя строка — самая частая причина провала гейта и самая дорогая в исправлении. Поэтому доли путей считаются в T0, до кода.

## Запрос 3 · Лиды против CRM

```sql
select date_trunc('week', created_at) as week, count(*)
from lead
where created_at >= current_date - 30
group by 1 order by 1;
```

Сверить с выгрузкой CRM за тот же период. Расхождение больше 3 % означает, что синк теряет или дублирует записи — чинить до продолжения.

## Запрос 4 · Целостность

```sql
-- экспозиции без ассета
select count(*) from exposure e
join creative_variant cv on cv.id = e.variant_id
where cv.asset_id is null;

-- варианты, которые не удалось разобрать
select variant_resolution, count(*)
from creative_variant group by 1;

-- экспозиции без волны
select count(*) from exposure where wave_id is null;
```

Первое должно быть нулём. Второе — доля `dynamic_unresolved` фиксируется как известное ограничение: эти экспозиции участвуют в решениях, но не в обучении. Третье — не блокирует, но волны надо проставить до первого анализа когорт.

## Наблюдение 5 · Переписывание истории

```sql
select * from v_restatement where day >= current_date - 30;
```

Не блокирует гейт. Нужно, чтобы узнать реальный размер эффекта у себя и при необходимости подвинуть `settled_window_days`. Если `spend_drift_pct` заметен и на 10-й день — окно надо расширять.

---

## Если гейт провален

Не «доделаем по ходу». Останавливаемся, чиним причину, перезапускаем сверку. Второй прогон через неделю — обязательный: разовое совпадение цифр ничего не доказывает.

Единственное допустимое послабление: если провален только критерий 2 и причина в неподключённом пути атрибуции, можно зафиксировать это как явное ограничение скоупа («WhatsApp-трафик в системе не учитывается»), сузить окно анализа до остальных путей и идти дальше. Но это решение записывается в README, а не забывается.
